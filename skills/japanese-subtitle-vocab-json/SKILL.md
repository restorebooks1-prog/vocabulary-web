# 日文字幕單字 JSON

先讀 [references/format.md](references/format.md)，遵守詞表 schemaVersion 2（目錄仍為 1）。使用者提供網站專案時，先讀其 data/catalog.json 與本次更新的既有詞表；不要覆寫其他詞表。

## 來源與選詞

- 必須有字幕、既有詞表或使用者提供的單字來源；無來源時請使用者提供，不編造正式內容。範例必須清楚標為示範。
- 以繁體中文協助只熟悉五十音、少量單字的學習者。先讀完全部來源，收錄影響人物行動、意圖、事件與轉折的所有重要詞、常用基礎詞與固定說法，不設詞數上限。不把一般助詞或單純活用規則當成詞彙。
- 合併同詞的活用形；term 寫辭書形，reading 寫完整假名，hint 保留字幕實際形式與對應讀音。meaning 只寫語境適用意思。不確定讀音註明待確認；不同讀法／語義確實影響理解時分列。
- category 按內容分組。首次時間取全部提供字幕中最早段的開始時間，秒數寫入 firstStartSeconds。period 以 floor(seconds / 180) 產生三分鐘分組；未知用 null 與「時間未知」，不從位置猜測。多集混合需以帶集數的 period 區分各集時間。
- 補充同份詞表時處理並合併全部已提供來源，去重並重新核對最早時間；保留既有資料的 ID，不因名稱、排序、分類、時間或意思修正而更換 ID。無法讀完須說明缺漏，不稱完整。

## 穩定識別與名稱

- collectionName 是作品／頂層分類名稱字串；itemName 是集數／任意子項目名稱字串。可為「海賊王／01集」，也可為「生活日文／買東西」，不要限定必須有集數。
- 詞表 id 在整站唯一，單字 id 在詞表內唯一；限小寫英數、底線與連字號，1～80 字元，首字為英數。新 ID 用穩定識別值，不用列索引；先尋找同來源既有詞表 ID。不同來源即使顯示名稱相同也不可共用詞表 ID。
- ID 一旦發布即為進度資料的對應鍵，不重新產生。新增詞只分配新 ID；刪除詞不重用舊 ID。

## 輸出與檢查

- 一份詞表存成 data/<id>.json，新增或更新 data/catalog.json 的對應分類與項目，名稱與 ID 必須完全一致。以 JSON serializer 寫 UTF-8，不手工拼接帶來源文字的 JSON，不輸出 JS 程式碼或 HTML。
- filters.categories 與 filters.periods 為所有有效選項，依詞表順序／時間順序去重。搜尋、只看未看過、只看標記由網站提供，不把個人的已選條件混入詞表 JSON。
- 詞表新增與更新只透過本機修改檔案並 git push 發布；不要建立網站上傳、匯入或匯出入口。使用者的勾選與目前篩選存於瀏覽器／Firebase，不加入公開詞表或 Git。只在使用者提供真實進度時保留，不自行宣稱記得跨裝置狀態。
- 在網站專案執行 node scripts/validate.mjs；核對來源涵蓋範圍、詞數、讀音、最早時間，以及 0、179.999、180、359.999、360 秒的分組。驗證器通過不代替語意核對。
- 預設只修改本地 JSON 並提供檔案；git push／發布須有使用者授權。回報處理範圍、詞數、輸出檔、驗證結果與尚待確認內容。

## 固定日文欄位

網站可依 JSON 顯示不同欄位，但本 skill 固定產出參照格式中的八個 columns，順序與 label 必須一致：已看過、標記、分類、單字／固定說法、假名讀音、本段意思、字幕形式／提示、首次出現時段。seen／marked 為 checkbox，其餘為 text。不因網站支援其他語言而省略假名或更換日文欄位。
